## <font style="color:rgb(15, 17, 21);">2. 核心理论与必背概念</font>
### <font style="color:rgb(15, 17, 21);">2.1 备份与恢复</font>
+ **<font style="color:rgb(15, 17, 21);">逻辑备份</font>**<font style="color:rgb(15, 17, 21);">：使用 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">mysqldump</font>`<font style="color:rgb(15, 17, 21);"> 导出成 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">.sql</font>`<font style="color:rgb(15, 17, 21);"> 文件（包含建表和数据）。优点是可读性强，跨版本恢复方便；缺点是恢复速度慢，适用于中小型数据库。</font>
+ **<font style="color:rgb(15, 17, 21);">物理备份</font>**<font style="color:rgb(15, 17, 21);">：直接拷贝数据文件（如 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">xtrabackup</font>`<font style="color:rgb(15, 17, 21);">）。速度快，适合几百 GB 的大库，但跨平台兼容性差。</font>
+ **<font style="color:rgb(15, 17, 21);">增量恢复</font>**<font style="color:rgb(15, 17, 21);">：利用 MySQL 的 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">binlog</font>`<font style="color:rgb(15, 17, 21);">（二进制日志）。如果不小心误删了数据，全量备份 + 重放 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">binlog</font>`<font style="color:rgb(15, 17, 21);"> 可以恢复到误删前一秒的状态。</font>

### <font style="color:rgb(15, 17, 21);">2.2 主从复制（读写分离基石）</font>
<font style="color:rgb(15, 17, 21);">为什么需要主从？因为单台 MySQL 的并发和存储是有极限的。通常我们会搭建 </font>**<font style="color:rgb(15, 17, 21);">一主多从</font>**<font style="color:rgb(15, 17, 21);"> 架构：主库负责写（增删改），从库负责读（查询）。</font><font style="color:rgb(15, 17, 21);">  
</font>**<font style="color:rgb(15, 17, 21);">核心原理（3 个线程）</font>**<font style="color:rgb(15, 17, 21);">：</font>

1. **<font style="color:rgb(15, 17, 21);">主库的 Binlog Dump 线程</font>**<font style="color:rgb(15, 17, 21);">：将数据变更（Binlog）发给从库。</font>
2. **<font style="color:rgb(15, 17, 21);">从库的 I/O 线程</font>**<font style="color:rgb(15, 17, 21);">：接收主库发来的 Binlog，写入本地的 Relay Log（中继日志）。</font>
3. **<font style="color:rgb(15, 17, 21);">从库的 SQL 线程</font>**<font style="color:rgb(15, 17, 21);">：读取 Relay Log，在从库重放 SQL 操作，实现数据同步。</font>

### <font style="color:rgb(15, 17, 21);">2.3 分库分表（海量数据解法）</font>
+ **<font style="color:rgb(15, 17, 21);">垂直拆分</font>**<font style="color:rgb(15, 17, 21);">：将不常用的字段（如文章正文 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">TEXT</font>`<font style="color:rgb(15, 17, 21);">）拆到副表；将不同的业务表（用户表、订单表）拆到不同的数据库。</font>
+ **<font style="color:rgb(15, 17, 21);">水平拆分</font>**<font style="color:rgb(15, 17, 21);">：单表超过 2000 万行时，查询极慢。按规则（如 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">user_id % 2</font>`<font style="color:rgb(15, 17, 21);">）将数据拆到两张表（</font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">order_0</font>`<font style="color:rgb(15, 17, 21);">, </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">order_1</font>`<font style="color:rgb(15, 17, 21);">）或多个库中。这也是为什么大厂禁止物理外键的原因（跨库无法使用外键）。</font>

## <font style="color:rgb(15, 17, 21);">3. SQL 与命令行实操案例</font>
### <font style="color:rgb(15, 17, 21);">3.1 备份与恢复实操</font>
<font style="color:rgb(15, 17, 21);">在你的终端里（不是 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">mysql></font>`<font style="color:rgb(15, 17, 21);"> 内部，是系统的命令行），执行以下命令：</font>

**<font style="color:rgb(15, 17, 21);">① 全量备份</font>**<font style="color:rgb(15, 17, 21);">（将 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">learn_mysql</font>`<font style="color:rgb(15, 17, 21);"> 库备份到 D 盘）：</font>

```plain
mysqldump -u root -p --databases learn_mysql > /d/github_repository/mysql-learning/backup.sql
```

**<font style="color:rgb(15, 17, 21);">② 模拟误删数据</font>**<font style="color:rgb(15, 17, 21);">：</font><font style="color:rgb(15, 17, 21);">  
</font><font style="color:rgb(15, 17, 21);">登录 MySQL，执行 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">DROP DATABASE learn_mysql;</font>`<font style="color:rgb(15, 17, 21);">（删库跑路）。</font>

**<font style="color:rgb(15, 17, 21);">③ 恢复数据</font>**<font style="color:rgb(15, 17, 21);">：  
</font><font style="color:rgb(15, 17, 21);">利用刚刚导出的 SQL 文件恢复：</font>

```plain
# 先重新建一个空库
mysql -u root -p -e "CREATE DATABASE learn_mysql;"
# 导入备份文件
mysql -u root -p learn_mysql < /d/github_repository/mysql-learning/backup.sql
```

_<font style="color:rgb(15, 17, 21);">(执行完再去 MySQL 里查，数据全回来了)</font>_

### <font style="color:rgb(15, 17, 21);">3.2 用户与权限管理</font>
**<font style="color:rgb(15, 17, 21);">最小权限原则</font>**<font style="color:rgb(15, 17, 21);">：绝不要在生产环境用 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">root</font>`<font style="color:rgb(15, 17, 21);"> 账号连接应用。通常会给 Python 项目单独建一个账号。</font>

```plain
USE mysql;
-- 创建一个 app_user，密码为 AppPass123!
CREATE USER 'app_user'@'%' IDENTIFIED BY 'AppPass123!';
-- 只赋予它对 learn_mysql 库的增删改查权限（不给 DROP 权限）
GRANT SELECT, INSERT, UPDATE, DELETE ON learn_mysql.* TO 'app_user'@'%';
-- 刷新权限
FLUSH PRIVILEGES;
```

### <font style="color:rgb(15, 17, 21);">3.3 Python 实战：连接池的简单概念</font>
`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">pymysql.connect()</font>`<font style="color:rgb(15, 17, 21);"> 每次连接都要经过 TCP 握手和权限验证，极度消耗资源。在生产环境中，我们通常使用连接池（如 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">DBUtils</font>`<font style="color:rgb(15, 17, 21);">）。这里仅作演示，了解其思想：</font>

```plain
# 概念演示（需先 pip install dbutils）
from dbutils.pooled_db import PooledDB
import pymysql

# 初始化连接池，最小 5 个，最大 20 个连接
pool = PooledDB(
    creator=pymysql, maxconnections=20, mincached=5,
    host='localhost', user='root', password='你的密码', database='learn_mysql'
)

# 从池子里拿一个连接（用完会自动还回去，不需要 conn.close()）
conn = pool.connection()
```

# 备份

**<font style="color:rgb(15, 17, 21);">作业 2（架构思考题）</font>**<font style="color:rgb(15, 17, 21);">：假设你的电商系统有 5000 万订单，用户查“我的订单”特别慢。如果你只能做一件事来优化，你选择加索引、加 Redis 缓存，还是分库分表？</font><font style="color:rgb(15, 17, 21);">  
</font>**<font style="color:rgb(15, 17, 21);">参考答案</font>**<font style="color:rgb(15, 17, 21);">：选择 </font>**<font style="color:rgb(15, 17, 21);">加索引</font>**<font style="color:rgb(15, 17, 21);">。</font><font style="color:rgb(15, 17, 21);">  
</font>**<font style="color:rgb(15, 17, 21);">解析</font>**<font style="color:rgb(15, 17, 21);">：先看 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">EXPLAIN</font>`<font style="color:rgb(15, 17, 21);">。如果查询条件是 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">WHERE user_id = 123</font>`<font style="color:rgb(15, 17, 21);">，但没建索引，全表扫描 5000 万行当然慢。加上索引后，查询只需 10 毫秒。如果不加索引直接上缓存或分库分表，就是典型的“过度设计”，不仅没法解决根本问题，还大幅增加了系统复杂度。</font>**<font style="color:rgb(15, 17, 21);">优化的第一原则：先找慢查询，看执行计划，再对症下药。</font>**

## <font style="color:rgb(15, 17, 21);">5. 踩坑复盘记录</font>
1. `**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">mysqldump: command not found</font>**`<font style="color:rgb(15, 17, 21);">：执行备份命令必须在系统终端，且 MySQL 的 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">bin</font>`<font style="color:rgb(15, 17, 21);"> 目录必须在环境变量中（我们在阶段 0 已经配过）。</font>
2. `**<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">Access denied for user 'app_user'</font>**`<font style="color:rgb(15, 17, 21);">：新建的账号如果没有授权 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">localhost</font>`<font style="color:rgb(15, 17, 21);"> 或者没有刷新权限（</font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">FLUSH PRIVILEGES</font>`<font style="color:rgb(15, 17, 21);">），Python 代码就连不上。检查账号和权限是否配置正确。</font>
3. **<font style="color:rgb(15, 17, 21);">备份文件乱码</font>**<font style="color:rgb(15, 17, 21);">：备份时最好加上 </font>`<font style="color:rgb(15, 17, 21);background-color:rgb(235, 238, 242);">--default-character-set=utf8mb4</font>`<font style="color:rgb(15, 17, 21);"> 参数，防止中文注释在恢复时乱码。</font>
